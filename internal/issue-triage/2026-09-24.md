### Review notes on #390 (not blockers, for whoever reviews it)

Recorded here rather than posted — commenting on another author's PR is outside this routine's
boundary.

- **`"external_tool" in assignment.get("submission_types", [])` raises `TypeError` if Canvas returns
  the key with a `null` value.** `dict.get(k, default)` returns the default only when the key is
  *absent*, not when its value is `None`; I confirmed the behavior directly
  (`'x' in {'submission_types': None}.get('submission_types', [])` → `TypeError: argument of type
  'NoneType' is not iterable`). The assignment dicts come straight off the Canvas payload with no
  normalization upstream. `.get("submission_types") or []` is the safe form. Low severity — Canvas
  normally returns a list, and **I have no live instance to measure whether it ever returns `null`
  here**, so this is a source-level hardening note, not an observed failure.
- **There is a real behavior trade-off the brief does not name:** a past-due external-tool assignment
  that genuinely was never done no longer appears as `OVERDUE` anywhere. It moves to an
  informational bucket labelled "Canvas does not report external-tool submission state." That is the
  PR's stated intent and it removes a false alarm, but it also removes a true one, and only the
  contributor has checked this against a live Gradescope-linked course. Worth a deliberate yes
  rather than an implicit one.
