### New since the 2026-11-04 brief — issue #564, and the feature it asks for largely exists

**#564 "[Bug]: support query with course names"** (`zqian`, opened 2026-11-05T21:50Z, `bug` label, no comments, reports version 1.16.1). It asks that tools taking `course_identifier: str | int` resolve a course *name*, describing `list_users` failing on a name and the model recovering by calling `list_courses` and retrying with the numeric ID.

**Read from the code, not reproduced — this routine cannot measure live Canvas behavior:** name resolution is already implemented. `list_users` (`admin_tools.py:124`) does call `get_course_id()`, and `get_course_id()` (`core/cache.py:126`) matches a course code, **name**, or bare SIS ID of one of the caller's courses, case-insensitively and ignoring surrounding whitespace, refusing an ambiguous match with `ValueError` before dispatching; `match_course` and `resolve_numeric_course_id` document the same rules. So the requested behavior is substantially present in the version the reporter ran.

That makes the likelier defect **the miss path, not a missing feature.** When no course matches, `get_course_id()` keeps its legacy pass-through: an identifier without an underscore is returned verbatim, so a course name that fails to match goes straight into the request path as `/courses/<name>/users` and Canvas answers 404 — which is exactly the "fails first" symptom reported. `CLAUDE.md` already draws this distinction: code that needs a numeric ID should use `resolve_numeric_course_id()`, which never hands back an unresolved string. Candidate framings for the maintainer, none verified: a name that misses because the caller's course list was not refreshed (`_refresh_after_miss` is shared and rate-limited); a course the caller can read but which is absent from their `/courses` list, such as an admin querying a course they are not enrolled in; or simply that the pass-through should become an explicit "course not found" error for a non-numeric, non-underscore identifier rather than a 404 from Canvas.

**No action taken.** Not commented on, not labeled, not assigned — a triage reply on a new external report is a maintainer judgment, and the reproduction needs live Canvas, which this routine cannot touch.
