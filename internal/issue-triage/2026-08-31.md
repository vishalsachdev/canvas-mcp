### c. Corrections and flags on the brief

1. **The draft reply asserts more than has been checked.** It says *"nothing jumps out as needing
   rework."* Three things do, all in the new `^\d+:\d+$` validation. Measured with the actual
   compiled pattern:
   ```
   '65532:65532'   -> True     '0:0'                    -> True   ← uid 0 == root
   '1000:1000'     -> True     '65532:65532\n'          -> True   ← Python $ matches pre-newline
   'not-a-number'  -> False    '٦٥٥٣٢:٦٥٥٣٢'            -> True   ← \d is Unicode without re.ASCII
   '-1:-1'         -> False    '99999999999999999999:1' -> True
   ```
   **`TS_SANDBOX_UID_GID=0:0` passes validation and runs the container as root**, with no warning —
   defeating PR #317's stated guarantee (the comment two lines above the call site still reads *"so a

   so it is a footgun rather than a vulnerability — but for a knob whose entire purpose is non-root
   enforcement, rejecting `0` is worth requesting. The other two are robustness nits: a trailing
   newline (plausible from a `.env`) and Unicode digits both reach `docker --user`, which fails
   loudly rather than escalating.
