**#411, the Codex P1 (`syllabus_body` returned unfenced) — CONFIRMED, and the brief understates
it in one respect while overstating it in another.**

Verified at source. `src/canvas_mcp/resources/resources.py` contains no reference to
`fence_untrusted` or any fencing helper at all (`grep` over `src/canvas_mcp/resources/`: zero
hits), and `get_course_syllabus` ends in a bare `return syllabus_body`. Meanwhile the *tool* that
returns the same payload is classified as requiring a fence —
`src/canvas_mcp/core/untrusted_content.py:111` maps `get_syllabus` to `_fenced("fence_untrusted")`,
and `src/canvas_mcp/tools/courses.py:351,358` applies it on both the plain-text and raw-HTML
branches. So the same Canvas field is fenced on the tool surface and raw on the resource surface.

Two things the brief did not have:

1. **The sibling resource has the identical gap, and it is live on `main` today.**
   `get_assignment_description` (same file) returns `response.get("description", "")` verbatim,
   while `get_assignment_details` is classified `_fenced("fence_untrusted")` at
   `untrusted_content.py:76`. Assignment descriptions are returned by
   `GET /courses/:id/assignments/:id` without any `include[]`, so that path is already populated
   and already unfenced, independent of #411.

2. **On the syllabus path specifically, #411 is what makes the gap reachable.** The only change
   #411 makes to this file is adding `params={"include[]": "syllabus_body"}` to the request
   (+3/−1, the whole diff). Canvas does not return `syllabus_body` from `GET /courses/:id` unless
   that include is passed — which is exactly why `courses.py:324` and `courses.py:472` both pass
   it. Before #411 this resource would fall through to "No syllabus available for this course."
   in the common case; after #411 it returns real instructor-authored HTML through an unfenced
   path. *Caveat, flagged per this routine's standing rule:* that reading is from the repo's own
   consistent internal convention and the Canvas API's documented behaviour, **not** from a live
   measurement — nothing here can call a real Canvas instance. It should be confirmed against an
   instance before being written down as fact anywhere public.

   Where the brief overstates: it frames this as "a real regression in coverage … that the #262
   registry-wide sweep apparently didn't catch". It is not a regression in the guard. The guard
   never covered this surface **by construction**: `tests/security/test_untrusted_content_registry.py`
   builds a `FastMCP`, calls `register_all_tools`, and enumerates `await mcp.list_tools(...)`.

   no tool-registry sweep can ever see them. That is a structural blind spot in the guard, which
