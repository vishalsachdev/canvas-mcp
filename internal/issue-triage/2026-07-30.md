**⚠️ HIGH-SENSITIVITY — #181 — "[Bug]: rubric not showing in assignment page after association"** (zqian, opened 2026-07-30T02:37Z, no comments yet)
zqian reports that `associate_rubric` returns a success message ("Rubric 361 has been successfully associated with Assignment...") but the rubric never actually appears on the assignment page in Canvas — confirmed reproducible, and they've verified the same rubric associates fine when done manually through the Canvas UI. They attached the raw API params their manual UI action sent (form-urlencoded `rubric_association[rubric_id]=...` etc.) versus what the MCP tool appears to be sending.

I checked the code and this is real, and it's the same class of bug as #180 (which you just fixed for the course-bookmark path in #182). `associate_rubric` (`src/canvas_mcp/tools/rubrics.py:1088-1121`) sends its `PUT /courses/:id/rubrics/:id` request with a plain JSON body — it never sets `use_form_data=True`, unlike `_ensure_course_bookmark`'s POST to `/rubric_associations` a few hundred lines up, which does. Canvas's rubric-association params use Rails bracket notation and appear to require form encoding; sent as JSON, the outer rubric PUT still returns 200 (so the tool reports success), but the nested `rubric_association` payload doesn't take, so nothing actually attaches. This is exactly the "assignment-path bookmark gap" flagged as unverified in the #180 follow-up.
