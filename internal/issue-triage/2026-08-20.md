- **#309 — "[Feature]: add support for content migration"**, opened by **`zqian`**
  (University of Michigan — high-priority external collaborator, owns #172), 2026-08-19
  19:25 UTC. No comments yet.

  Requests a `content_migrations`-backed tool so an instructor can copy/import content
  from one course (or a template course) into another — assignments, discussions, etc.,
  with `date_shift_options` and progress polling via the Progress API. Checked the repo:
  grep for `content_migrations` / `course_copy` / `migration_type` across `src/` returns
  **zero hits** — no tool calls that Canvas API. PR #191's quiz work only *mentions*
  `content_migrations` as a future QTI-import prerequisite, nothing implemented.

  **Not wholly new ground, though:** `skills/canvas-course-builder/SKILL.md` already has
  a "Clone from Existing Course" mode (`get_course_structure` on the source, preview, then
  recreate matching modules/pages/assignments/discussions in the target). It's explicit
  that this is **structure only** — "Content is not copied when cloning... For content
  migration, copy page bodies using `get_page_content` + `create_page`" — so it's a
  manually-orchestrated, per-item workaround built from existing tools, not the native
  Canvas copy API. #309 is asking for the real thing (single async call, full fidelity
  including files/quizzes/rubrics, no per-item recreation), which is a materially
  different and larger piece of work than the skill covers — but the reply should
  acknowledge the existing partial workflow rather than imply there's nothing here at all.

  Worth flagging as a design question before scoping: content migration is a
  **write across two courses at once**, with delayed/queued completion (the Progress API
  callback), and can silently overwrite grading structure, due dates, or existing content
  in the target course depending on `selective_import`. That's a materially bigger blast
  radius than the single-course write tools already shipped, and doesn't fit neatly into
  the existing `STUDENT_WRITE_TOOLS`-style allowlist since it's instructor-only by nature
  (Canvas requires manage-content permission on both courses).

  Draft reply:
  ```
  Thanks for filing this with the payload example — that's helpful, and it's a real gap.
  The closest thing today is canvas-course-builder's "clone from existing course" mode,
  but that only recreates structure (module/page/assignment names) by reading one course
  and rebuilding items in another — it explicitly doesn't copy content or use Canvas's
  own copy API. Nothing in the codebase calls content_migrations.

  Before I scope a tool, a few things I want to get right given the blast radius: a course
  copy is a write into an existing target course, it runs async (Progress API polling,
  not a single request/response), and depending on selective_import it can touch grading
  structure, due dates, and existing content the target course already has. I'd want the
  tool to default to a dry-run/preview of what would be copied, require explicit
  confirmation before the real migration kicks off, and surface Progress API failures
  (partial imports, individual item errors) rather than reporting bare "started" success.

  Two questions that would shape the design: (1) do you need selective import (pick
  specific assignments/discussions/etc.) from day one, or is "copy everything" enough for
  a first version with selective import as a fast follow; (2) is date_shift_options a hard
  requirement for your workflow, or can that wait? Selective import is the bigger lift of
  the two (Canvas's copy-parameters format for choosing individual items is its own small
  API surface), so knowing whether you need it now changes the estimate a lot.
  ```
