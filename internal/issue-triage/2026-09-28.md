### Corrections and additions to the brief

Three things the brief did not surface. All three are reviewer-relevant, and none of them is
measured against live Canvas — I cannot make live Canvas calls any more than the brief's author
can, so treat these as readings of the diff, not confirmed behavior.

1. **The change relabels; it does not remove items from the bucket.** A graded `on_paper` midterm
   still appears under `⚠️ Missing Submissions`, now as `NOT SUBMITTED` rather than `OVERDUE`. The
   PR's own new test asserts exactly this (`assert "Status: NOT SUBMITTED" in midterm`). So the
   author's reported 10 false OVERDUE items become 10 false NOT SUBMITTED items, and the
   `Missing Submissions (N)` header count is unchanged. The brief describes the effect as those
   assignments "stop being misreported as overdue", which is true, but the draft reply's stronger
   phrase — "closes a real gap for on_paper/none-type assignments" — overstates it. The author was
   straight about this: they filed the header-count problem as a separate follow-up. Worth being
   explicit in any reply that this lowers the severity of the false positive, not its count.

2. **OVERDUE now depends entirely on Canvas populating `missing`.** The new branch is
   `elif submission and submission.get("missing")`. If any Canvas instance or endpoint returns a
   submission object where `missing` is absent or null, every past-due unsubmitted assignment
   silently downgrades to NOT SUBMITTED and OVERDUE becomes unreachable. The PR's evidence is one
   live account (14 courses, 90 assignments), which cannot rule that out across instances. This is
   the same shape as the failure class this repo already tracks — a confident answer resting on an
   unchecked premise about what Canvas returns (#199, #234). A good question for the author: did
   any of those 90 submissions come back with `missing` **absent**, as opposed to `False`?

3. **The fixture edit in the existing test is load-bearing, not cosmetic, and it demonstrates (2).**
   `test_get_my_submission_status_overdue_comparison` had `{"workflow_state": "unsubmitted"}` and
   asserted OVERDUE; the PR adds `"missing": True` to it. Without that edit the old test fails
   under the new code — precisely because a submission dict lacking a `missing` key no longer
   produces OVERDUE. Expected for a deliberate behavior change, but it means the only thing now
   standing between "Canvas omits the key" and "OVERDUE never fires" is Canvas's own consistency.
