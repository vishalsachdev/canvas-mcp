### #381 spot-verification — the docs are right, but the recommended form is the fragile one

The brief calls the addition "accurate on read." The shape is right — +22/−1 to `README.md`, one
new `<details>` block matching the existing per-client pattern, plus adding Codex to the supported
clients sentence. But the brief's read is a read, and the PR makes a load-bearing claim about
runtime behaviour that is worth measuring, because the block leads with the form that breaks.

The PR says, under `codex mcp add canvas-api -- /abs/path/.venv/bin/canvas-mcp-server`:

> The server loads `CANVAS_API_URL` and `CANVAS_API_TOKEN` from the repository's `.env` file.

Measured A/B, editable install, python-dotenv 1.2.3, `src/canvas_mcp/core/config.py:12` calling
bare `load_dotenv()`, with a `.env` in the repo root and `CANVAS_API_URL` unset in the environment:

- cwd = repo root → `URL= https://example.test/api/v1` (loaded)
- cwd = anywhere else → `URL= None` (**not** loaded)

So resolution follows the **process cwd**, and an editable install does not rescue it: the `.env`
sitting next to the code is not found when the server is launched from elsewhere. Codex launches
MCP servers from the session's working directory, so the `codex mcp add` one-liner works only
while the user happens to be inside the repo, and fails with missing credentials otherwise. The
PR's own `~/.codex/config.toml` + `cwd` fallback is the form that always works — it is presented
second, as the exception ("If Codex starts the server from another working directory"), when it is
really the rule. That is a review note, not a defect: nothing in the PR is false.

Two things follow from the same measurement, both for you, neither actionable by me:

1. `CLAUDE.md`'s Agent Plugins bullet states `load_dotenv()` "resolves against the calling module,
   not CWD." The A/B above shows the opposite on the installed path. That inverts the bullet's
   conclusion — it argues a plugin would need an explicit path in `load_dotenv()`, when
   `cwd: "${PLUGIN_DATA}"` alone would in fact do it. The bullet is a watch item with no owner, so
   nothing is blocked on this, but the note is wrong as written. I did not edit it: outside
   `internal/issue-triage/`.
2. The same cwd-sensitivity is a real ergonomic sharp edge for every stdio client, not just Codex.
