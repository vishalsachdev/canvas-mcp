### 4. #423 — measured the regression the brief flagged as an open question

Yesterday's brief raised, as an unresolved question, whether `submission.missing` being *absent*
(rather than `false`) loses the OVERDUE signal, and whether assignments with no `submission`
object at all lose their only OVERDUE signal. I turned that into a measurement rather than
leaving it as a reading.

The diff replaces a `due_at < now` comparison with `elif submission and submission.get("missing")`.
I ran the same three past-due payloads through the real `get_my_submission_status` tool on both
trees (mocking only `fetch_all_paginated_results` / `get_course_id` / `get_course_code`, so the
tool's own branching and formatting are exercised):

| payload (all past due) | `origin/main` `2885c5c` | PR #423 `62879d8` |
|---|---|---|
| `submission` key entirely absent | OVERDUE | **NOT SUBMITTED** |
| `submission` present, `missing` key absent | OVERDUE | **NOT SUBMITTED** |
| `submission` with `missing: True` (control) | OVERDUE | OVERDUE |

So the brief's concern is **confirmed at the code level, on two payload shapes**, and the PR's
new tests cover neither: the added cases supply `missing: True` and `missing: False` only. A
past-due assignment for which Canvas does not set `missing` is silently downgraded from OVERDUE
to NOT SUBMITTED in a student-facing overdue list — which is the tool's whole purpose.

**What remains unmeasured, and must not be asserted to the contributor:** whether real Canvas
ever actually omits `submission` or omits `missing` on a past-due assignment. That needs a live
instance, which neither the triage agent nor I have. The PR's premise — that Canvas's own flag
is more trustworthy than a client-side date comparison — may well be right; the gap is the
fallback when the flag is absent, not the flag itself. Any reply must frame the two rows above
as "this is what the code does on these inputs", not as "Canvas does this".

Flagging accordingly: yesterday's draft reply for #423 (carried forward by reference in this
brief, not reproduced) **asserts unmeasured Canvas behavior as if confirmed** in its discussion
of absent-vs-`false`. It should be reworded to separate the measured code behavior above from
the unmeasured Canvas-payload question before it is ever posted.
