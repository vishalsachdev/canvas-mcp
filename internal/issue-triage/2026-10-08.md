```
Thanks for taking a swing at OAuth support — this lines up with #236, which I've had open for a while.

Before I can review this, I need to ask for some changes.

First, the structural one: this branch shares no git history with the repo's current `main` — there's no common ancestor at all, which is why GitHub shows it as conflicting and can't offer a rebase. It can't be resolved in place. You'd need to re-create it as a fresh branch off current `origin/main`, carrying only the auth commits.

That aside, on scope and content:

1. The PR bundles in a `scripts/` directory and a deployment doc that look like your own course-grading workflow rather than part of the OAuth feature — about 3,200 of the 3,791 added lines. Some of it looks like it carries real student and rubric identifiers, and a personal file path. Please drop `scripts/` and `docs/CHATGPT_OIDC_DEPLOYMENT.md` (which also hardcodes a personal domain) entirely.

2. Please split what's left into two focused PRs: the Canvas-side token-refresh flow, and the MCP-facing OIDC gate for the hosted server. They're different features and much easier to review separately.

3. A few changes in `rubrics.py` would regress safeguards that landed after your fork diverged, so you likely couldn't have seen them:
   - the `use_rubric_for_grading` guard changes from `if not use_rubric_for_grading:` to `if use_rubric_for_grading is False:`, which lets an absent or null field through to a write. `tests/tools/test_rubric_grading_safety.py::test_precheck_failure_never_writes` covers exactly that case on `main` today.
   - `submission[posted_grade]` is now written unconditionally on every `grade_with_rubric` call from the server's own arithmetic, instead of deferring to Canvas's rubric-to-grade mapping. `test_grade_outcome_uses_canvas_score_and_ignored_criteria` asserts that key is absent.
   - `associate_rubric` still carries the old nested-JSON `PUT` that `main` replaced with bracket-notation form data — the old form made Canvas return 200 while the association was silently never created — and the PR adds a second nested-dict `PUT` to `/assignments/:id` without `use_form_data=True` on top of it.

4. `core/anonymization.py` drops `'url'` from `identifying_fields` in `anonymize_submission_data`. I follow the rationale that an `online_url` submission's URL is the graded work product, but a submission URL can itself carry a student identifier, so that's a privacy-tier change that needs its own discussion rather than riding along with an auth PR. Note also that `main` has since moved anonymization to a single gate at the client layer, so the structure being edited here no longer exists upstream.

5. The token-refresh path needs test coverage — right now the only test covers the redirect-allowlist check. A PR description explaining the design would help too.

I haven't approved CI to run on this yet and won't until the diff is scoped down to just the auth work. Appreciate you putting this together — mainly I want to make sure no student data ends up in a public PR.
```
