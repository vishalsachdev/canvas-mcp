### #564 — "[Bug]: support query with course names" (zqian)

Opened 2026-11-05T21:50Z by `zqian`. No comments yet. Report: calling a course-identifier tool (they tested `list_users`, typed `course_identifier: str`) with a course **name** instead of a code/ID fails; a second call to `get_course_details` with the same name also fails; only after the client separately calls `list_courses` to resolve the name to a numeric ID does `list_users` succeed on retry. They're asking that course-identifier tools resolve a plain course name themselves, the way they already resolve a course code.

**Unverified analysis, not a confirmed root cause:** both `list_users` (`src/canvas_mcp/tools/admin_tools.py:130`) and `get_course_details` (`src/canvas_mcp/tools/courses.py:252`) already call `get_course_id()`, and `get_course_id`/`resolve_numeric_course_id` in `src/canvas_mcp/core/cache.py` already do match by course **name**, not just code — see the `CourseRecord` tuple at `cache.py:254-259` (id, course_code, name, sis_course_id) and `_match_course` at `cache.py:268-281`. The matching there is an **exact, case/whitespace-insensitive equality check** against the Canvas `name` field (`_alias_key`, `cache.py:263-265`), not a fuzzy or substring match. On a plain miss in stdio mode, `get_course_id` doesn't raise an error — it silently passes the raw string straight through as a fallback "identifier" (`cache.py:185-193`; a name containing an underscore instead gets wrapped as `sis_course_id:<name>`, but still 404s the same way), which then 404s against Canvas as a literal path segment, producing the generic "Error fetching ..." the user saw. A second plausible cause: `_match_course` raises an explicit ambiguity error, not a silent miss, when a name collides with another course's own code or name (`cache.py:268-281`) — that would read differently from a 404, so it's distinguishable once we see the actual error text. My best guess is still a paraphrase/partial-title miss falling into the silent pass-through, but I haven't reproduced either path against a real course list, so treat this as a hypothesis, not a diagnosis. If the paraphrase-miss theory is right, the fix is either a substring/fuzzy name-matching mode (ambiguity risk: multiple courses could share a substring) or a clearer "not found, try list_courses" error instead of silently 404ing.
