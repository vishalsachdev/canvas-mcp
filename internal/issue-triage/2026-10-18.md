- **`mcp` 2.1.1** (`uv.lock:980-981`) — **CVE-2026-59951** / GHSA-84m7-p3x7-pcfv. Fixed in `mcp` 1.30.0 (1.x) and 2.2.0 (2.x). Affected: 1.8.0–1.29.1 and 2.0.0–2.1.1.
- **What it is:** a Streamable HTTP server in *stateful* mode never reclaims session state — sessions never expire, a client `DELETE` leaves the entry registered, a refused first request leaves a running task, and session count is unbounded. An endpoint-reachable client can grow server memory without bound with ordinary short requests; only a restart reclaims it. The advisory notes explicitly that authentication limits *who* can open sessions, not *how many* a token holder can open.
- **This server appears not to be exposed.** `src/canvas_mcp/server.py:867` serves HTTP via `mcp.http_app(stateless_http=True)`, and the advisory's "Not affected" list names "servers on 1.12.0 or later passing `stateless_http=True` (no sessions are kept)" and "servers using only the stdio or SSE transports". fastmcp forwards the flag (`fastmcp/server/server.py:673` passes `stateless=stateless_http` into the HTTP app built at `fastmcp/server/http.py:51,61`). Every stdio install (`.mcpb`, local server) is out of scope regardless. **Caveat:** this is a code read of fastmcp 4.0.3 as installed in this sandbox. I did not exercise the hosted Azure deployment and claim no runtime measurement of it.
