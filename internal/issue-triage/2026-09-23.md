### #391 — Installation challenges (@dmalpiCS)

They installed the Claude Desktop Extension (`.mcpb`) on Windows 11 and it fails to launch, with
Claude Desktop showing:

```
Command: uv
Arguments: run --directory C:\Users\dm\AppData\Roaming\Claude\Claude Extensions\local.mcpb.vishal-sachdev.canvas-mcp canvas-mcp-server
Error: spawn uv ENOENT
```

They're asking for a recommended install path, and ideally one where they don't have to manage
`uv` themselves at all.

**Unverified root-cause analysis** (read from source, not reproduced on a live Windows machine):
`manifest.json:21-22` hardcodes the launch command as the bare string `"uv"` with no absolute path
and no bundled/vendored `uv` binary — it relies entirely on `uv` being resolvable on PATH at the
moment Claude Desktop spawns the subprocess. `ENOENT` from `spawn` is the standard Node/Electron
error for "command not found on PATH." On Windows specifically, GUI-launched applications
(Claude Desktop included) typically inherit the PATH that was captured at the last sign-in/login,
not a live view of it — so installing `uv` *after* that snapshot (or without a subsequent
sign-out/sign-in or reboot) can leave a fresh terminal working fine while any already-running GUI
app still can't see it. That would explain a Windows-specific `ENOENT` on an otherwise-correct
install. This is plausible, not confirmed — I have no Windows sandbox to test it in.

```
Thanks for the detailed error output — that's exactly what I needed to narrow this down.

The extension currently launches the server with a bare `uv` command, relying on it being
resolvable on your PATH, rather than a full install path. Windows GUI apps like Claude Desktop

Desktop was already running (or since your last full sign-in), the extension can't see it yet —
even though `uv --version` works fine in a brand-new terminal.

Could you try:

1. Open a *new* Command Prompt or PowerShell window and run `uv --version`. If that fails too, the

2. If `uv --version` works in a fresh terminal but Claude Desktop still can't find it, try fully

   Claude Desktop inherits.
3. As a workaround in the meantime, you can skip the extension and do a full manual install

   - Clone the repo and set up a virtualenv:
     ```
