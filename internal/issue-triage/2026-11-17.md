### Corrections to the brief

**1. #595 is not "low risk" — it changes this repo's Claude workflow permission model.** The brief calls it "Low risk — CI-workflow-only version bumps, no source changes." The files changed are indeed workflow-only, but the `anthropics/claude-code-action` bump crosses **v1.0.273, which Dependabot's own PR body labels a breaking release with new security defaults**, including:
- *Sessions start in auto mode.* A safety review now decides tool calls that no allow rule covers, so **`--allowedTools` is no longer a strict list**, and workflows with a `prompt` can edit workspace files without an allow rule.
- *Code-running commands are denied on outside pull requests* when the PR author lacks write access, even if `claude_args` allows them (the run still succeeds — only a log warning).

This repo's workflows are exposed to the first item. `claude-code-review.yml`, `auto-label-issues.yml` and `weekly-maintenance.yml` all pass `--allowed-tools` as what they treat as a strict allowlist (for example `weekly-maintenance.yml` limits the session to `Bash(gh issue list:*),Bash(gh issue view:*),Bash(gh label list:*),Read,Glob,Grep,WebSearch`). The upgrade notes say sessions keep the earlier defaults only if `allowed_non_write_users`, `allowed_bots`, a custom `ANTHROPIC_BASE_URL` or `path_to_claude_code_executable` is set, or if the `settings` input is a file path or sets another permission mode. I grepped `.github/workflows/` for all of those knobs plus `--permission-mode` and `restrict_untrusted_prs`: **none is set anywhere.** So after this merge those four sessions switch to auto mode and their allowlists stop being strict. That is a deliberate decision, not a rubber-stamp bump.
